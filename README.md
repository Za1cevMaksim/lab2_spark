# Лабораторная работа 2

## Описание
Исследование производительности Apache Spark на кластере Hadoop с различным количеством DataNode (1 и 3). 
Сравнение базовой и оптимизированной версий Spark-приложения с использованием кэширования, репартиционирования и настройки shuffle.

## Датасет

https://www.kaggle.com/datasets/viridianachow/online-retail-uci-dataset

**Online Retail** 
- **Строк:** ~542k
- **Столбцов:** 8 (InvoiceNo, StockCode, Description, Quantity, InvoiceDate, UnitPrice, CustomerID, Country)
- **Типы данных:** int, double, string, date

# Дайте права на выполнение

### Память

Наблюдается четкая тенденция к снижению пикового потребления памяти:
1DN Base: 811.50 MB (Максимальная нагрузка)

3DN Opt: 691.30 MB (Оптимальная конфигурация)

Оптимизация (.repartition(4), .persist()) и масштабирование на 3 узла позволили снизить потребление памяти примерно на 15%.

### Скорость выполнения 
Время выполнения составило от 9.53с до 10.94с. Разброс незначителен.

Оптимизированная версия (Opt) показала время чуть выше, чем базовая (Base).

Это могло произойти из-за overhead оптимизаций для небольшого файла (всего 50 Мб): Операции repartition и принудительный count для кэширования добавляют накладные расходы на планирование задач Spark. Для файла такого размера проще прочитать его линейно (как в Base), чем перераспределять по партициям.
